## 分析與建議

**1. sam-showcase 目前沒有專屬的 GA4 Property，這是最優先要處理的**——不是「裝了追蹤碼但沒數據」，是連可以裝的 Property/Measurement ID 都還不存在。GTM 容器（`GTM-TXDXTHST`）已經建立，但容器本身不含 GA4 追蹤——GA4 Configuration 標籤需要一組 Measurement ID（`G-XXXXXXXXXX`），這組 ID 來自一個屬於 sam-showcase 的 GA4 Property + Web Data Stream，目前完全沒有。下一步：手動在 GA4 後台建一個新 Property（或授權我用擴大範圍的 OAuth 建），拿到 Measurement ID 後才能繼續 `ga-setup` 的標籤設定。

**2. 網站被 Google 索引成 4 種不同的 URL，很可能缺少 URL 正規化**——同一個首頁被拆成 `http://www.sam-showcase.com/`、`https://sam-showcase.com/`、`https://www.sam-showcase.com/` 三種不同寫法個別統計曝光（分別 7、1、4 次），代表 Google 把它們當成三個不同頁面在排名，SEO 訊號被分散掉，不是集中在一個「正確」的網址上。建議檢查：(a) 是否有把 `http://` 導向 `https://`、`www.` 導向不帶 `www.`（或反過來，擇一堅持）的 301 轉址，(b) 頁面 `<head>` 是否有 `<link rel="canonical">` 明確宣告哪一個是正式網址。這個問題不解決，其他 SEO 努力的效果會被打折扣。

**3. 搜尋曝光的關鍵字都是人名/品牌詞，不是「一個人產品團隊」「軟體外包」這類服務型關鍵字**——目前會被搜尋到，主要是有人直接搜你的名字，不是透過想找相關服務的人自然發現。如果目標是吸引潛在客戶/合作機會（不只是認識你的人搜得到你），現有內容（首頁的 "Software, shipped with care" 標語 + 專案索引）對 SEO 來說，可能缺少能命中「一個人接案」「全端工程師作品集」這類意圖字詞的內文——值得評估首頁/About 頁要不要加一段更具體描述服務範圍的文字。

**4. LCP 4.3 秒偏慢（Google 建議 2.5 秒內為「良好」），但 CLS 是滿分 0、TBT 只有 30ms**——版面穩定、互動延遲都很好，問題集中在「最大內容繪製」這一項，通常代表首屏最大的圖片/文字區塊載入偏慢。首頁 hero 是大字級的 serif 標題文字（不是圖片），LCP 元素比較可能是 Google Fonts（Instrument Serif／Noto Serif TC）還沒載入完成、文字用預設字型先畫一次再換字型（或反過來被 `font-display: swap` 卡住）——值得檢查字體載入策略（例如加 `<link rel="preload">` 對應字重、或評估是否真的需要等到 Noto Serif TC 這種較大的中文字型檔載完才能算「內容就緒」）。

**5. Accessibility 93 分不是滿分，SEO/Best Practices 都已經 100**——技術面 SEO 跟最佳實踐已經做得很好，可以之後有空再挑 accessibility 的扣分項目來看，不是急迫問題。
